# Decisions and deviations

Format: what · why · how to undo. Spec = CLAUDE.md v1.1.

## Stack
1. **pnpm via corepack, not a global pnpm.** The build machine had no pnpm; `corepack pnpm …` uses the version pinned in `package.json`.
2. **Raw SQL (`apps/api/src/schema.sql`) on Postgres 16, with embedded PGlite for local development — not Prisma.** *Should*-level deviation from §4. Prisma cannot run on PGlite, and the dev machine has no Docker/Postgres. The schema follows §6 table-for-table (snake_case), keeps the `(player, round, chance)` unique constraint and adds a partial unique index so a player can have only one active attempt. Production uses `DATABASE_URL=postgres://…` and the same SQL. Undo: generate a Prisma schema from `schema.sql` (`prisma db pull`) if the team prefers Prisma.
3. **Page parts store their text as `fields` (JSON) instead of one `en/hiReference/bhashiniDraft` per part row.** Tables and charts have many strings each (cells, labels, legend, source) under one tick group (§6). Every string is a field `{key, en, hiReference, draft, locked, numeric}`; plain parts have one field `t`. Scoring, editing and the console all work field-by-field.
4. **Server runs TypeScript with `tsx`** (no separate build step); the web app is built by Vite.

## Product
5. **Sahayika panels use a bright royal-blue gradient instead of `--navy #22293B`.** The client asked for a light, bright, game-like orange/white/blue theme with no dark surfaces (23 Oct). White text on the blue gradient keeps ≥ 4.5:1. Undo: `.sahayika-panel` in `apps/web/src/index.css`.
6. **Inline glossary help (client request, 23 Oct).** Glossary terms in the English source are underlined; tapping one offers the CAG Hindi and variants with "जोड़ें" into the matching Hindi part. Words worth a second look in the draft (glossary avoid-forms and planted slips) get a dotted underline; tapping offers replacements (none for slips — their fixes are never sent). To limit noise, source underlines cover page terms, multi-word glossary entries and single words ≥ 8 letters whose Hindi is not a transliteration. An avoid-form that appears in CAG's own Hindi for the page is never flagged (the automatic split in `seed/glossary.json` marks e.g. कंपनी as an avoid-form of "company").
7. **Returning players may sign in with email + OTP only** ("पहले खेल चुके हैं?" link on the registration screen) instead of refilling the form.
8. **Leaving counts include a page reload** (the page is hidden while it reloads). This matches "one count per departure" literally; revisit if officers complain.
9. **A > 40-character single insert is rejected** (treated as paste, §12), including from automation; e2e tests type character by character.
10. **Trial round has no tick groups**; completion is sentences (§1). The source panel highlights the English sentence that matches the caret position.
11. **Chat refusal line** for "translate paragraph/sentence/page for me" requests is authored in `strings.sahayikaExtra.refuseTranslate` (the script has none). These never reach the LLM.
12. **Grammar tip texts** (`strings.grammarIssues`) and all other strings added during the build are listed in `_authoredInSpec_reviewBeforeLaunch`.

- **D5 Anuvad scorer**: `scoring.provider = "local"`; no Anuvad adapter call is made yet (contract not supplied).

- **D7**: `ANUVAAD_XLIT_AUTH` sent as `Authorization` when set.
- **D8 office Hindi names**: console → Offices → batch-translate (needs `DHRUVA_NMT_KEY`), then review row by row.
- **D10 login**: email OTP via `SMTP_URL`; dev code `123456` only when `NODE_ENV` is development/test and no SMTP is set. Optional `ALLOWED_EMAIL_DOMAINS`.
- **D12 certificate**: built per §13 with a "(नमूना)" signatory placeholder.
- **Dhruva ASR binary frame event name** is not in the reference PDF; configurable `DHRUVA_ASR_DATA_EVENT` (default `data`). Confirm with BHASHINI. Until keys are set, voice typing falls back to the browser's Web Speech API (hi-IN).
- **TTS service ID** not supplied: `DHRUVA_TTS_SERVICE_ID`; until set Sahayika speaks through the browser's `speechSynthesis` (en-IN, female voice preferred).

## Seed content
- `seed/pages/primary_r38_7.json`, `secondary_r38_49.json`, `pro_r38_2.json` were built from Report 38 by reading the Hindi PDF pages visually (its text layer is broken). **Every part is `needs_verification`.** Drafts are *sample-authored* machine-style Hindi with 6–7 planted slips each (`draft_status: sample_authored_not_bhashini`) because no NMT key was available; regenerate with "Generate BHASHINI draft" once keys are set, then re-mark slips. Report 38 has no headnote boxes, footers or annexure references; see each file's `notes`. Terms "turnover", "yield" and "process" were deliberately not used because CAG's own Hindi uses forms the glossary lists as avoid-forms.
- Only one page per round exists, so the same page repeats across chances in development (`SEED_ALLOW_UNVERIFIED=1`, shown to players as "नमूना सामग्री"). Each round needs ≥ 3 verified, published pages for review (§19).

## Scoring concern for CAG to decide
Submitting BHASHINI's draft **unchanged and immediately** scores about 60 / 66 / 71 in प्राथमिक / माध्यमिक / वृत्तिक (completion 0, but time full and chrF against the reference already high). That passes 33 and earns ~31 credits without editing. See PROGRESS.md "Needs a decision".

## Iteration 2 (23 Oct, client feedback)
13. **English-first UI.** `config.ui.locale = "en"`; all player text in `content/strings.en.json` (Hindi file kept; fallback key-by-key). Sahayika lines show their `en` text. Hindi for the whole UI is to come from the **BHASHINI website-translation plugin** (`config.ui.translationPlugin.enabled/scriptUrl`; the script is injected only when enabled — its host must be added to the CSP in `deploy/nginx.conf`). The workbench (English source page and the player's Hindi) is marked `translate="no"` + `notranslate`, so a page translator can never translate the source for the player. Round names in English use `nameEn` ("Trial Round"…); titles use new `titleEn`/`titleMeaning` config fields. The certificate follows the locale.
14. **Sahayika never auto-speaks by default.** Settings → voice: Off / Only when I tap Listen (default) / Auto. Every line has Listen ⇄ Pause/Resume and Stop; a floating audio dock appears while she speaks; she stops on scene change.
15. **Game feel:** scene transitions (framer-motion), Title as start screen, profile-created reward scene, 4-step training, rules cards, **Journey map** hub, **Mission briefing** with 3-2-1-GO (server clock starts after GO), round HUD (level medal, chance pips, circular timer that changes colour + icon at 5 min / 1 min, checkpoint progress, reward pool; HUD sticky), red edge glow in the last minute, floating "+1 sentence / Part cleared!" text, particle bursts, synthesized SFX + phone haptics, "Mission complete / Time's up" stamp → scoring scene → report card (count-up score, title medal reveal, coin cascade, stars, next goal), Hall of Fame.
16. **Accessibility settings:** text/HUD size (S–XL), high contrast, reduce motion (also honours the OS setting), sound on/off + volume, vibration. Status is never shown by colour alone (icons/text accompany every state). Hover motion is disabled on touch screens so taps never miss a moving button.
17. **BHASHINI services:** service IDs in `config.bhashiniServices` (NMT `ai4bharat/indictrans-v2-all-gpu--t4`, ASR Hindi `ai4bharat/conformer-hi-gpu--t4`, TTS English female `Bhashini/IITM/TTS`). One ULCA inference key `DHRUVA_API_KEY` serves all tasks unless a per-task key is set.

A best Trial score ≥ `levels.trialQualifyingScore` (default 33, editable in the console) unlocks Primary, Secondary and Pro, each independently playable with its own attempts, timer, score and report card. Parts carry `pageNo`; the workbench shows a page navigator when a bundle spans several pages. 23. **Console settings.** `PUT /admin/config/settings` edits time, credit cap and pages per level, the Trial qualifying score, pass mark, chances and the five scoring weights; validated (credits = 50, weights = 100) and audited.
24. **Leaderboard** (`GET /leaderboard`): top 10 by credits then stars, shown as first name + last initial and office city/state, with the player's own rank. **Session ID** is created at sign-in, stored on every attempt and shown on the report card.
25. **Trial content from a report's closing section.** Report 38 has no "Conclusion"; chapters end with "Summing up" (सारांश). `seed/pages/trial_r38_conclusion.json` uses Chapter IV's Summing up (327 words, 12 long sentences). The earlier Trial passage stays as a second page so a replay shows different content.
26. **Railway Finance sample (reference/sample-report).** Delivered as Word files with clean Unicode Hindi (no OCR needed). **The English is the 2022-23 report (year ended March 2023) and the Hindi is the 2023-24 report (year ended March 2024)**, so they are not a parallel pair and cannot be used for scoring until the matching edition is supplied. English has Chapter 4 and more annexures than the Hindi set.
27. **Draft engine.** Drafts are pre-generated per part when content is ingested (never live during play), batched 25 per call × 5 parallel with number masking. The client asked for CAG's own Anuvaad document-translation pipeline instead of the Dhruva NMT curl; its endpoint and contract are still awaited, so Dhruva NMT remains the default.

## Iteration 4 — professional portal, real report bundles, Anuvaad workbench (23 Oct)

28. **All levels open for the 27 Oct review.** `levels.unlockRule` is now `"all-open"` (default): Trial, Primary, Secondary and Pro are playable from the start; the Trial is still suggested first ("warm-up"). The Trial-first rule (`"trial-pass-unlocks-all"`) is one switch away in the console Settings. API tests pin the Trial-first rule; shared tests cover both.
29. **Visual language.** The playful look was replaced by a professional game-portal style in the CAG Anuvaad palette (`reference` → Anuvaad `design_guidelines.json`): navy `#0B2545`, saffron `#E85A1A` for primary actions, gold `#C49B3D` for rewards, slate surfaces, 8/12 px radii. The header is left-aligned (CAG logo + brand, portal nav, credits, profile menu, BHASHINI logo) — a deliberate deviation from the centred title in §7, for a web-portal feel.
30. **Signed-in portal.** After OTP the header shows the player's avatar (initials), name and office, with a menu: My profile, Levels, Leaderboard, Score & certificate, Settings, Sign out. New pages: `/profile` (player card, rank, level records, 10 achievements, attempt history) and `/leaderboard` (All-India / my state / my office, podium, own row pinned, gap to the next rank). Endpoints `GET /me/profile`, `GET /leaderboard?scope=&limit=`, and aggregate-only `GET /stats/public` for the landing page.
31. **Onboarding as recruitment.** The landing page sells the challenge (season ladder with credits per level, why-play perks, three-step how-it-works, live aggregate stats); registration shows a live player card and the reward track (+2 now, up to 50). Copy for the UI and all 194 Sahayak lines was rewritten in a professional coach voice (gender-neutral Sahayak, no feminine self-verbs in Hindi).
32. **Real 10 / 20 / 30-page bundles from Report 38.** English segmented from the PDF text layer (`scripts/content/segment_en.py`, PyMuPDF), CAG's Hindi transcribed from the rendered Hindi PDF pages (the Hindi text layer is broken), tables kept as grids, charts/photos kept as cropped images with editable caption, labels and source (`figure` part type). Selection (no page repeats across levels): Primary = Executive Summary vi–x + Ch II 7–8 + Ch VI 57–59; Secondary = Ch IV 34–41 + Ch V 43–52 + Ch VI 53–54; Pro = Ch I 1–6 + Ch III 9–19 + Ch IV 21–33. ≈ 3.7k / 8.5k / 12.1k English words. Built by `apps/api/src/scripts/build-bundles.ts` into `seed/pages/*_r38_bundle.json`; the old single-page seeds moved to `seed/pages-archive/`. Trial stays on the Executive Summary p. v passage and the Chapter IV "Summing up". All references are marked `needs_manager_verification`. Where an English sentence runs across a page break, the Hindi is split at the nearest clause (or repeated) and flagged with a `note`.
33. **Drafts from CAG's Anuvaad pipeline.** `bhashiniServices.translationProvider: "anuvaad"` sends draft translation to `https://anuvaad-backend.bhashini.co.in/v1/pipeline` (same IndicTrans2 model; no Dhruva key needed; optional `ANUVAAD_XLIT_AUTH`). Live tests showed the spec's `⟦n⟧` masks come back as bare digits and unmasked numbers get reordered, so masks are sent as `{n}` (returned intact and in place). Drafts are translated sentence by sentence; when a mask is still lost, the version keeping more real numbers wins. ~60 of ~580 parts still miss a number — a genuine MT omission the player must fix; the workbench QA panel names the missing figure.
34. **Glossary matching = Anuvaad algorithm** (`reference/glossary-matching-algorithm.md`): one normaliser for terms and text (lowercase; non-word → space), n-grams up to 6, longest first across the whole text, no token matched twice, exact match only, sector-specific entries first and general entries kept ("sector widens, never narrows"), indexes built once and cached until the glossary changes. Character offsets are kept for in-place underlines. The xlsx's only sector entry (staff → कार्मिक, Railways) is now a separate entry beside the general one. Bundle scoring terms are chosen from matched terms that CAG's Hindi actually uses (if CAG uses an accepted variant, it leads), excluding connectives, verbs, generic words and D3-overridden words.
35. **Workbench in the Anuvaad layout.** Main levels show one row per segment (English source | editable BHASHINI draft, aligned), tables/figures stacked within their row, a focused-segment highlight, and a sticky context panel: the segment's glossary terms (ranked approved forms, one-click insert, sector label, avoid-forms struck), live QA checks (empty fields, numbers kept, English words left, flagged words, full stop) and page progress. The Trial keeps the two-panel passage layout.
36. **Payload size.** API responses are compressed (`@fastify/compress`); the 30-page Pro round drops from ≈ 1 MB to ≈ 130 KB on the wire.
37. **Console** (built in this iteration): admin portal with KPI dashboard (registrations/activity trends, engagement funnel, score histograms, measure breakdown, credits distribution, fair-play signals, top offices/states, content usage, most-missed glossary terms, service health), players with guarded reset/delete, content library + "Add a report" bundle ingest, full evaluation/game settings incl. unlock rule and chrF constants, danger-zone reset of test data. A deleted player's session is treated as signed out.
38. **Test data reset.** The development database (all e2e/probe players and the test login) was moved aside to the scratchpad and reseeded fresh on 23 Oct; content, glossary and offices reload from `seed/`. `SEED_REFRESH_PAGES=1` reloads rebuilt bundles over sample pages.
